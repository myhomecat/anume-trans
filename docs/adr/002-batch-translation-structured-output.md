# ADR-002: 배치 번역 결과를 문자열 파싱이 아니라 스키마로 받는다

- 상태: 채택
- 날짜: 2026-09-03

## 배경

배치 번역은 프롬프트로 번호 형식을 지시하고, 응답을 줄 단위로 파싱했다.

```python
prompt = "... 번호를 유지해서 출력해줘.\n\n형식:\n1. [번역결과]\n2. [번역결과]"
for line in result.strip().split("\n"):
    if ". " in line:
        _, translation = line.split(". ", 1)
        translations.append(translation.strip())
```

이 파싱은 LLM이 지시한 형식을 정확히 지킨다는 가정에 의존한다. 실제로는 어긋난다.

- 만화 대사는 원래 여러 줄인 경우가 많다. 번역이 두 줄로 나오면
  두 번째 줄에는 `". "` 가 없어 **버려지고**, 이후 인덱스가 전부 밀린다.
- `1)` `1．`(전각) `**1.**`(마크다운) 처럼 번호 표기가 바뀌면 해당 항목이 통째로 누락된다.
- 원문이 `…` 이나 효과음이면 LLM이 그 번호를 생략하기도 한다.
- 서두에 "알겠습니다. 번역해드리겠습니다." 같은 문장이 붙으면 `". "` 를 포함하므로
  **첫 항목으로 잘못 들어가** 전체가 한 칸 밀린다.

밀림의 결과는 예외가 아니라 **잘못된 화면**이다. 대사가 엉뚱한 말풍선에 렌더링되고,
에러도 로그도 남지 않는다.

기존 폴백은 이것을 잡지 못한다.

```python
out.append(res[i] if i < len(res) else original)   # 개수가 모자란 만큼만 원문으로 채움
```

개수가 우연히 맞으면서 순서만 밀린 경우는 그대로 통과한다.

## 결정

tool use 를 형식 강제 용도로 사용해, 인덱스를 명시적으로 받는다.

```json
{"items": [{"index": 1, "text": "..."}, {"index": 2, "text": "..."}]}
```

- `tool_choice` 로 해당 도구 호출을 강제한다. 실행할 함수는 존재하지 않으며,
  전달된 인자 자체가 결과다.
- 받은 뒤 **개수와 인덱스 집합을 검증**한다. 하나라도 어긋나면 그 청크는 원문으로 폴백한다.

## 이유

- 파싱 코드가 사라진다. 형식 준수 여부를 LLM의 성실성에 맡기지 않는다.
- `index` 가 명시적이므로 순서가 뒤바뀌어도 복원할 수 있고,
  누락되면 **검출된다**. 지금은 검출되지 않는다는 점이 가장 큰 문제였다.
- 실패를 조용히 통과시키지 않는다. 대사 밀림은 화면에 나온 뒤에는
  사람이 원문과 대조하지 않는 한 발견되지 않는다.

## 대가

- CLI 경로에서는 쓸 수 없다. SDK 경로에서만 동작하므로 ADR-001이 선행되어야 한다.
- 스키마가 프롬프트 토큰을 조금 더 먹는다.
- 검증을 강화하면 폴백(원문 노출) 빈도가 늘어날 수 있다.
  잘못된 번역이 표시되는 것보다 원문이 남는 편이 낫다고 판단했다.

## 검증

- 번역 결과 개수 == 입력 개수
- 인덱스 집합 == `{1..n}` (중복·누락 없음)

둘 중 하나라도 실패하면 해당 청크 전체를 원문으로 되돌리고 경고를 남긴다.
