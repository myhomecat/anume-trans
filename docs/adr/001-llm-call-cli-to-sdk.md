# ADR-001: LLM 호출을 Claude CLI(subprocess)에서 SDK로 옮긴다

- 상태: 채택
- 날짜: 2026-09-03

## 배경

번역 단계는 `claude` CLI를 셸로 호출해 구현돼 있었다.

```python
cmd = f'claude -p "{escaped_prompt}" --output-format text'
process = await asyncio.create_subprocess_shell(cmd, ...)
```

프로토타입 단계에서는 이 방식이 가장 빨랐다. 인증·SDK 설치·키 관리가 전부 불필요했고,
로컬에 이미 로그인된 CLI를 그대로 재사용할 수 있었다.

그러나 실제로 굴려보니 세 가지가 걸렸다.

1. **배포가 불가능하다.** 실행 호스트에 `claude` CLI가 설치되어 있고 로그인 상태여야 한다.
   레포를 클론한 사람은 번역 단계를 실행할 수 없다.
2. **출력 형식을 강제할 수 없다.** 텍스트만 돌아오므로 JSON을 받으려면
   `result.find("{")` / `rfind("}")` 로 문자열에서 긁어내야 했고,
   배치 번역은 `"1. 번역결과"` 형식을 정규식 없이 `split(". ", 1)`로 파싱하고 있었다.
   이 파싱은 대사에 줄바꿈이 있거나 LLM이 번호 형식을 바꾸면 조용히 어긋난다(ADR-002).
3. **셸 이스케이프가 취약하다.** 프롬프트에 따옴표·백틱·`$`가 섞이면 깨지고,
   `create_subprocess_shell` 이라 셸 메타문자 주입 여지가 남는다.

## 결정

`anthropic` 공식 SDK(`AsyncAnthropic`)로 호출한다.
단, 기존 CLI 경로를 삭제하지 않고 **프로바이더로 분리**해 둘 다 유지한다.

- `ANTHROPIC_API_KEY` 가 있으면 SDK를 쓴다 (기본값).
- 없으면 기존 CLI 경로로 폴백한다.

## 이유

- 배포 가능성이 이 프로젝트에서 가장 큰 제약이었다. 공개 레포이므로
  "클론하면 돌아간다"가 성립해야 한다.
- SDK는 tool use / structured output을 지원한다. 이것이 ADR-002의 전제 조건이다.
- 모델을 인자로 바꿀 수 있어 단계별 티어링(번역=Haiku, 이미지 분석=Sonnet)이 가능해진다.
  CLI로는 프로세스마다 동일 모델이 강제된다.
- 토큰 사용량이 응답에 실려 오므로 비용을 계측할 수 있다.

## 대가

- API 키가 필요하다. 종량 과금이 발생한다(번역만 하므로 페이지당 수 원 수준).
- 의존성이 하나 늘어난다(`anthropic`).
- CLI 경로를 남겨두므로 호출 경로가 두 개가 된다. 폴백이 조용히 동작해
  "SDK로 도는 줄 알았는데 CLI였다"가 생길 수 있어, 기동 시 어느 경로인지 로그로 남긴다.

## 후속

- ADR-002: 배치 번역의 문자열 파싱을 structured output으로 교체
